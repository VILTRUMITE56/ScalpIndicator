Start with the [31 October assessment and improvement plan](docs/IMPROVEMENT_PLAN_2026-10-31.md) and its implementation update. The local P1 indicator now includes an off-by-default B4 anti-chase experiment (>1.0 trigger ATR from EMA20), with extension and rejection-reason outputs; TakeProfit working copy v29 matches and compiles, but B4 is not validated for profitability or mirrored in the strategies. The local P1 strategy reserves the frozen 15 bp scenario once and emits candidate execution reasons. The isolated P2 strategy source also passed TakeProfit compile and runtime_quick on 5,000 bars. Its two-year native platform backtest could not run because the connected plan permits 5,060 bars versus 210,240 requested; a bounded platform probe returned zero trades, insufficient history, and a last-bar timestamp outside the requested period. The P1 one-position shadow replay is negative at all cost cases under assumed full fills; see its [report](research/reports/p1_portfolio_shadow_report.md). The updated indicator remains unsaved because the working copy is based on v16 while v19 is latest; the strategy copy still differs from local source. A separately tested P2 target aims for more than $5 net after modeled costs but loses in the inspected replay, so P1 remains the reference and profitability is unproven.

The [project assessment and upgrade roadmap](docs/PROJECT_LEVEL_UP_ASSESSMENT.md) evaluates the current evidence, compares established indicator families, derives the default cost/ATR feasibility constraint, and prioritizes the next work. Economic feasibility, shared signal/entry rules, and reliable data come before adding optional filters.

Current TakeProfit drafts differ from the reproducible local P1 source, and the active chart binding is unknown. See the [source reconciliation](research/SOURCE_RECONCILIATION_2026-10-31.md) and the [paper-shadow capture workflow](research/paper_shadow/README.md); its run template intentionally blocks capture until source, venue, fees, filters, and funding are confirmed.

This repository contains a frozen B0 reference and a versioned P1 candidate implementation for a TakeProfit BTC perpetual research indicator and strategy. P1 unifies touch/recovery/trigger state and planned entry/SL/TP through one generated Indie block. The next-bar open is a plan quote; the strategy's ±2 bp limit is an execution quote, and actual fills remain unknown. The #4-audited two-year replay contains 6,815 candidate triggers after masking disputed source bars and matches eligible-bar counts exactly. The #7 shadow study finds 291 candidates pass the existing 15 bp cost/R and stop gates. A separate one-position portfolio replay retains 168 conditional entries after rounded sizing and overlap limits; its 10/15/20 bp modeled results are negative. Actual orders and fills remain unknown. See the [P1 contract and reproduction guide](research/README_CANDIDATE_P1.md), [candidate report](research/reports/candidate_parity_report.md), [economics report](research/reports/candidate_economics_report.md), [P1 portfolio report](research/reports/p1_portfolio_shadow_report.md), [P2 net-target feasibility report](research/reports/p2_net5_target_feasibility_report.md), [current assessment](docs/CURRENT_ASSESSMENT.md), and [results](RESULTS.md).

## TakeProfit setup

The connected TakeProfit indicator working copy v29 matches the current local indicator and compiles, but remains unsaved because it is based on v16 while v19 is latest. The strategy working copy v21 remains different from local. The previous exact local indicator/strategy sources passed compile plus runtime_quick on 5,000 bars before the B4 change; the updated indicator's runtime quick was not run. The fixed-window backtests still do not provide adequate history to estimate profitability. No alerts or automation are configured.

The code supports 5-minute execution with a completed 15-minute EMA(20/50) trend, and 15-minute execution with a completed 1-hour EMA(20/50) trend. It resets the bias and warms up again after a timestamp gap; it requires 250 completed higher-timeframe bars. The dashboard shows the chart instrument, current model levels, estimated cost in R, and historical filter counts. Its markers and levels are chart-model outputs using an assumed bar-open fill, not guaranteed fills or exchange-position tracking.
