## Baseline behavior at a glance

- Research proxy: Binance BTC/USDT perpetual (`BTC/USDT.P`, `CXBNF8`). The user's eventual execution venue and account fee tier are still unspecified.
- Profiles: 5m execution with completed 15m bias; 15m execution with completed 1h bias. Both require 250 complete higher-timeframe bars.
- Direction: completed HTF close and EMA20/EMA50 alignment with a 3-bar EMA50 slope condition. Execution indicators are EMA20, EMA50, and ATR14.
- Pullback: current code searches completed candle indices `[2]` through `[4]` for EMA20 range intersections and selects the newest intersection, then checks the EMA50 close rule. If that newest intersection fails the close rule, it does not substitute an older touch. It freezes touch ATR and a structural extreme/invalidation, then allows a trigger from touch age 1–6 bars.
- Trigger: closed directional body beyond EMA20, EMA50, and the preceding candle extreme. A consumed setup cannot retrigger; recovery above/below EMA20 is required before a newer touch.
- Risk: ATR stop floor 1.0x, 2.5x cap, 1.5R target, cost eligibility 15bp round-trip assumption capped at 0.20R, 0.25% research risk. Strategy limits the entry around the next bar open by 2bp and uses 5bp commission per execution.
- The indicator's open-price reference is assumed, not an exchange fill. Candle-only stop/target evaluation handles a same-candle collision stop-first/ambiguous. No timed exit is enabled.

See the JSON specification for the complete side-mirrored rule text and execution assumptions. Its `signal_rules_as_implemented` section deliberately records actual rolling-touch code behavior; it does not silently substitute a proposed first-touch rewrite.

## Verification and restore

On 30 October 2026, the canonical strategy v16 and indicator v24 working copies each passed TakeProfit `runtime_quick` on 5,000 bars. This verifies compilation/execution on the sample window only; it does not establish realtime reload parity, order correctness, full historical coverage, or profitability. Request IDs and summaries are in the manifest.

To restore the frozen code, check out this repository revision and use the two canonical `.indie` files above. The indicator's unsaved v24 platform copy is based on v16 while saved platform v19 is newer; the source manifest records this unresolved platform divergence. The local research baseline remains restorable without loading a temporary MCP copy.

Regenerate source/result hashes and the run inventory from the repository root:

```powershell
node research/build_baseline_manifest.mjs
node research/audit_v1.mjs
```

The first command writes `research/BASELINE_MANIFEST.json`; the second rechecks the historical ledger accounting and v1 overlapping-exit finding. It does not rerun a trading backtest.
